# Default-agent model shortlist

> Historical five-role shortlist (2026-10-03). Superseded by the [October model audit](research-model-audit-2026-10.md) and [current six-role guide](default-agents.md), including researcher and cheap-first tasker recommendations.

Research date: **2026-10-03**. This note compares only the 13 candidates requested for the five bundled roles. Suggestions are advisory display aliases, not runtime model IDs, pins, or availability guarantees. Model/role suitability is an inference from public evidence, not a local agent benchmark.

## How the evidence is used

- **Architect:** prioritize reasoning, requirements coverage, tool use, and long-context reliability; accept slower generation for consequential decisions.
- **Coder:** prioritize repository implementation and terminal/tool benchmarks, then interactive latency. Arena Code is a useful frontend preference signal, not proof that a patch passes tests.
- **Reviewer:** prioritize careful code reasoning and independent verification. Coding benchmarks are indirect evidence; without a matched defect-detection/false-positive evaluation, do not claim a review-precision winner.
- **Tasker:** prioritize complete few-step latency and adequate instruction/tool reliability. High-effort flagship benchmark results do not establish fast behavior at the bundled `low` setting.
- **Writer:** prioritize creative-writing preference and voice-preserving edits. General reasoning and coding scores are secondary, and writing preference does not establish factual or citation accuracy.

### Speed and benchmark caveats

[Artificial Analysis performance methodology](https://artificialanalysis.ai/methodology/performance-benchmarking) describes rolling 72-hour median speed measurements and normalized token counts. Its website default workload is 10K input tokens; a model page or provider route can use different settings. Record the endpoint, effort, and workload when disclosed. Output tok/sec excludes time-to-first-token; for reasoning models, first token is not necessarily first answer token. Unspecified settings remain unspecified.

For a tool-driven job, the useful approximation is the sum over calls of initial latency plus generated tokens divided by output speed, plus tool execution and retries. A fast decoder can still lose on total latency through a large reasoning budget, slow startup, or repeated failed calls. Do not confuse aggregate hardware throughput or AA-AgentPerf service-level thresholds with measured per-request output speed.

[Arena's ranking method](https://arena.ai/blog/ranking-method) reports raw scores/ranks alongside confidence intervals and rank spreads. Overlapping rank spreads imply ties; a small raw-score lead is not a reliable win. [Arena's FAQ](https://arena.ai/faq) describes blind human preference and Bradley–Terry ratings. Compare within the same category and snapshot, never creative-writing scores directly against Code scores. Style and verbosity can influence preference.

Vendor benchmark tables are labeled as such. Different benchmark versions, agent harnesses, effort settings, and token budgets are not a common tournament. Missing measurements are not zero scores, and predecessor results do not become evidence for an unverified exact model name.

Muse-max's provider page distinguishes **24.99s first chunk** from **34.87s first answer** despite its excellent 202.3 tok/sec throughput. Fable-max's provider/model pages report **247.63s first chunk/FAQ-labelled TTFT** at a **10K-input** workload. These are reasons not to choose either as an unqualified low-latency tasker. Muse workload and matched low/high speeds were not established.

Gemini-high's **10K-input** provider page is internally inconsistent across extracted sections: the table gives **236 tok/sec and 21.76s median first chunk**, while its FAQ gives **248.6 tok/sec and 16.13s first answer**; the researcher's earlier table gave 242 tok/sec. MiMo's provider FAQ reports **269 tok/sec / 8.12s first answer** on PrimaLabs, but that extract did not establish workload or effort. These are optional route-specific observations requiring endpoint-equivalence checks, not typical speed for every deployment. The separately named `mimo-v2.6-pro-ultraspeed` and Grok fast variant were excluded.

### Task benchmarks and harness effects

- **Matched independent terminal evidence:** the [AA Claude comparison](https://artificialanalysis.ai/models/releases/comparisons/claude-sonnet-5-5-vs-claude-opus-5-5) reports Terminal-Bench **4.0** at **high**: Opus **56.6%**, Sonnet **43.9%**; at **max**: Opus **59.6%**, Sonnet **63.6%**. The [Sol/Astra comparison](https://artificialanalysis.ai/models/releases/comparisons/gpt-6-1-sol-vs-gpt-6-astra) reports high **51.5% / 54.0%**, max **56.1% / 59.1%**. Sonnet's vendor **70.6%** is not this independent score. Prefer Opus for hard correctness-first work; Sonnet's speed makes it attractive for interactive iteration, not universally stronger at high effort.
- **Matched independent repository evidence:** [DeepSWE](https://deepswe.datacurve.ai/), updated September 22, runs a common mini-swe-agent harness. GLM-max **69% ±3%** and Kimi-max **69% ±5%** overlap. Neither is a demonstrated winner over the other. Vendor releases instead report **66.9 / 67.5**, with their own harnesses and settings. GLM's [official card](https://huggingface.co/zai-org/GLM-5.3/raw/main/README.md) also reports **84.5 CyberGym / 54.4 ExploitBench**; vulnerability-discovery evidence is not a review false-positive evaluation.
- **Muse:** [AA's launch analysis](https://artificialanalysis.ai/articles/muse-spark-1-3) reports Terminal-Bench **2.1** at **85% xhigh / 86% max**, versus Meta's vendor **88.8 max**. Meta's [official scorecard](https://research.meta.ai/articles/introducing-muse-1-3/benchmarks/benchmark-scorecard-v6.webp) gives DeepSWE **75.4**, AutomationBench **49.6**, DeepSearchQA **90.3** at max. Do not mix the launch article's old index **61/62** with the current **45/48** scale.
- **Fable:** [Anthropic's launch](https://www.anthropic.com/claude-fable-and-mythos-5-1) reports Terminal-Bench **4.0 55.8%**, CursorBench **3.2.0 73.4%**, HLE with tools **65.0%**. Production safeguards can fall back to other Claude models on some security/biology interventions; these are not necessarily pure-model results.
- **DeepSeek:** [official card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/raw/main/README.md), maximum effort, reports DeepSWE **74.2** and Terminal-Bench **2.1 90.6**, but **4.0 31.2**. Its Pi-harness scores are **66.2 DeepSWE / 86.1 Terminal-Bench 2.1**, with multi-sample settings. Pi-specific evidence is useful, but is not a prediction for a low-effort, few-call tasker.
- **Gemini:** [official card](https://deepmind.google/models/model-cards/gemini-3-8-flash/) reports DeepSWE **73.7%**, Terminal-Bench **2.1 89.4%**, **4.0 19.1%**; effort/harness was not established from the fetched table. The separately named Cyber variant was excluded.
- **MiMo:** [official checkpoint card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL/raw/main/README.md) reports DeepSWE **71.9**, Terminal-Bench **4.0 34.9**, Toolathlon-Verified **76.9**, CyberGym **94.0**. API/checkpoint equivalence was not independently established; the release article's RL trajectory ends at **72.6 DeepSWE**, a separate reported result.
- **Grok:** [vendor launch](https://x.ai/news/grok-4-7) reports DeepSWE **71.0% high**, Terminal-Bench **4.0 37.6%** in a mostly xhigh table. Another model-card excerpt says **38.0%** terminal; retain that discrepancy. No Grok row was found on the fetched independent DeepSWE board.

Official Sol announcement: [API launch post](https://community.openai.com/t/gpt-6-1-sol-in-the-api-a-meaningful-cost-performance-step/1402388), **75.2% DeepSWE high**. Its main launch page was blocked; [the model reference](https://developers.openai.com/api/docs/models/gpt-6.1-sol) confirms the exact identity. Astra's [launch](https://openai.com/index/gpt-6-astra/) was also blocked to direct retrieval; indexed vendor reasoning claims were not needed to decide the shortlist. Luna's weak low-effort index and [Agent Arena](https://arena.ai/leaderboard/agent/overall) max net improvement **1.35% ±1.07%, #25** argue for acceptance-tested mechanical work only; that metric is not task success or Elo.

**Why Grok is not in a final four:** it remains a credible coder/architect alternative with high-effort vendor DeepSWE evidence, but its independent coding/writing preferences and xhigh startup observation did not displace these finalists. Muse's strong coding signals did not make it a top-three writer; Astra's high reasoning index did not override its weaker collected writing preferences.

## Exact identity and adapter caveats

- Claude aliases resolve to `claude-opus-5-5`, `claude-sonnet-5-5`, and `claude-fable-5-1` in official docs: [Opus](https://platform.claude.com/docs/en/models/opus-5-5/overview), [Sonnet](https://www.anthropic.com/claude/sonnet), [Fable](https://platform.claude.com/docs/en/models/fable-5-1/overview). The exact **Fable 5.1** route is verified in this research; predecessor Fable 5 scores were excluded.
- OpenAI references confirm [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), and [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). GPT-6.1 Sol is not GPT-6 Sol.
- [Gemini documentation](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) confirms `gemini-3.8-flash` and low/medium/high support; `minimal` is unsupported.
- The requested `deepseek-v4.1-flash` is now used consistently as the **advisory alias**. [DeepSeek's API](https://api-docs.deepseek.com/) calls this version `deepseek-flash`; do not pin the advisory string as a guessed direct-provider ID. Its numeric effort controls require the adapter's actual mapping.
- [GLM](https://huggingface.co/zai-org/GLM-5.3/raw/main/README.md) and [Kimi](https://forum.moonshot.ai/t/kimi-k3-is-here-our-most-capable-model/480) document low/high/max, not a literal medium. [Kimi's limitations](https://www.kimi.com/blog/kimi-k3) warn about excessive proactiveness and unstable quality if historical thinking is not replayed. That matters for architect delegation and the smallest-change contract.
- [Grok docs](https://docs.x.ai/developers/models/grok-4.7) support low/medium/high/xhigh, default high. Do not substitute its fast variant.
- [MiMo API docs](https://mimo.mi.com/models/en-US/mimo-v2.6-pro) confirm the exact model and thinking on/off; a low/medium/high enum was not verified. Check adapter support before applying the coder's high label.
- [Meta's model page](https://developer.meta.com/ai/models/muse-spark/) distinguishes standard `muse-spark-1.3` from `muse-spark-1.3-contributor`, whose requests can improve products. Do not silently substitute the contributor tier for confidential code. [The updated release](https://research.meta.ai/blog/introducing-muse-spark-1-3) confirms max availability; launch-time access statements can be stale.

## Availability and validation

Resolve an actual provider/model ID and supported tool/effort configuration before pinning anything. These advisory lists do not alter the existing thinking levels, tool policies, or runtime selection. Validate finalists on representative local jobs: accepted patches for coder, confirmed defects and false positives for reviewer, plan coverage for architect, exact acceptance checks and full latency for tasker, and blind voice-preservation preferences for writer.
