# October 2026 model audit

Research cutoff: **2026-10-04 local time / 2026-10-03 UTC**. This is an audit of the five existing bundled lists and evidence for a sixth, `researcher`. It is not a claim about releases later in October. All suggestions remain advisory aliases, not automatic routing, guaranteed availability, or exact provider/model pins.

## Method and audit outcome

Selection policy: recommendations depend on role-specific capability, quality, cost, and speed—not API format, SDK adapter compatibility, provider access, or deployment convenience. Pi's `pi-ai` SDK abstracts API differences. Release/access/API facts below are descriptive source metadata, not shortlist gates. Audited core policy: architect prioritizes heavyweight Opus/Astra/Fable; researcher's calibration-led core is Argon/Muse/Sonnet. Final user edits add Kimi to architect, GPT-5.6 Sol to researcher, GLM/Grok to coder, and Muse to writer; these preferences are preserved in the release. GPT-5.6 Sol has no matched row in the October scorecard below: do not transfer GPT-6.1 Sol's rates to it. Argon also qualifies for writer on task evidence.

Read full primary model catalogs, model references, pricing pages, release pages, and checkpoint cards through authorized shell HTTP retrieval. Cross-check with the primary Artificial Analysis (AA), Arena, and DeepSWE pages, rather than relying on search snippets or model memory. No API inference requests or local model tournament were run.

The [October 3 packet](research-default-agent-models.md) is **substantially corroborated**, not a collection of invented future names. The official catalogs really do list Claude Opus/Sonnet 5.5, Claude Fable 5.1, GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna, and Gemini 3.8 Flash. The exact DeepSeek, GLM, Kimi, Muse, and MiMo identities also have official pages/cards. Its limits are important:

- It deliberately compared **13 requested candidates**, not every competitive current release. Omitting Gemini 4 Argon, Gemini 3.5 Flash-Lite, GLM-5.3-Flash, and MiMo-V2.6-Flash was not evidence that those models lose.
- It did not give a usable official price comparison. Sonnet-low has excellent bounded-task latency, but is **not the cheap tasker default** at $2/$10 per million tokens. Use coder for quality escalation instead of making the inexpensive role a flagship shortlist.
- It already labels benchmark/harness and reasoning-effort differences correctly. Preserve those distinctions, especially for a researcher and the low-effort tasker.
- AA speed and index observations move. A few re-fetched values differ slightly from that packet; these are retrieval-time observations, not frozen historical measurements or promises.
- Earlier merged evidence-research/architect routing is superseded by the requested separate researcher. Writer remains an evidence consumer, not a live-retrieval role.

The [AA methodology](https://artificialanalysis.ai/methodology/performance-benchmarking) uses rolling 72-hour medians except weekly 100K-input measurements represented over 14 days. Website default is roughly 10K input and at least 1,500 answer tokens; shorter tasker prompts may behave differently. Output tokens/sec measures streaming after the first chunk and excludes startup. Thus Flash-Lite's 360 tok/sec does **not** make it the lowest-latency option in this snapshot. Conversely DeepSeek's non-reasoning measurements do not establish its shipped `low` performance. Measure the selected endpoint and effort rather than silently turning off thinking.

## Researcher-specific model evidence

A researcher needs reliable tool calling, source discrimination, long-context synthesis, code navigation, explicit uncertainty and traceable citations. A model with strong prose preference is not automatically a good evidence collector; an advertised built-in search tool is not a substitute for this harness's available retrieval route.

- **Muse Spark 1.3 standard:** [official model scorecard](https://dev.meta.ai/models/muse-spark) reports **DeepSearchQA 90.3**, **SWEAtlas CodeBase QnA 59.4**, MRCR 256–512K **98.5** and 512K–1M **98.1**, at its published max configuration. These are unusually direct browsing, codebase-understanding and context signals. They are **vendor results**, not a matched October research-agent tournament. Its 200+ tok/sec observed decoding in the [existing packet](research-default-agent-models.md) coexists with substantial first-answer delay; the reported effort and first-answer delay matter when interpreting its task quality and speed.
- **Kimi K3:** [official release](https://www.kimi.ai/blog/kimi-k3) reports **BrowseComp 90.4** at 1M context with no context management; its main comparison uses context compaction at 300K. Source notes also mix models' different coding harnesses. Kimi is a credible deep-browsing/codebase alternate, not proven cheaper or more faithful than every current model.
- **Opus/Sonnet/Sol:** repository, long-context and tool reasoning support consequential synthesis. Opus is the quality/judgment tier; Sonnet/Sol are balanced tiers. HLE-with-tools and general index results are indirect support, **not proof of correct citations**.
- **Gemini 3.8 Flash:** native PDFs, multimodal input, tool use, URL context, 1M context, and independent repository evidence make it an economical evidence-reading/synthesis candidate. Use medium/high for investigation; tasker-style low is not necessarily enough for conflicting sources. Neither Search support nor scientific benchmark results prove broad web-research completeness.

No current matched benchmark in the fetched evidence establishes a universal winner for codebase research plus internet research, source coverage, fabricated citation rate and cost/latency in this manager's child harness. “Best” here means a defensible **evaluation shortlist**, with different tiers for different constraints.

### Hallucination-conscious researcher scorecard

Re-fetched the [primary AA-Omniscience page](https://artificialanalysis.ai/evaluations/omniscience) and inspected its embedded model records (`omniscienceBreakdown.accuracy`, `hallucinationRate`, and `omniscience`), not inferred chart values. This is a retrieval-time snapshot within the stated cutoff; figures are rounded.

| Model / measured effort | Hallucination rate ↓ | Factual accuracy ↑ | Omniscience index ↑ | Compact-list decision |
| --- | --- | --- | --- | --- |
| Gemini 4 Argon / high | 15.1% | 49.9% | 42.35 | Include first: best uncertainty calibration among these capable candidates. |
| Muse Spark 1.3 / max | 32.9% | 43.6% | 25.00 | Include: lower bad-guess rate plus direct browsing/codebase evidence; lower factual coverage disclosed. |
| Sonnet 5.5 / max, default fallback | 47.0% | 54.0% | 32.30 | Include: complementary code/tool synthesis and better calibration than remaining listed alternatives. |
| GPT-6 Astra / max | 51.3% | 62.6% | 43.40 | Architect candidate; not the research calibration preference. |
| Kimi K3 / max | 53.2% | 47.6% | 19.70 | Trim despite strong vendor BrowseComp; weaker calibration in this snapshot. |
| GPT-6.1 Sol / max | 54.3% | 62.1% | 41.53 | Trim: high factual coverage, but more bad guessing than the selected trio. |
| Gemini 3.8 Flash / high | 55.2% | 54.6% | 29.55 | Trim: token economy does not offset weaker calibration for this role. |
| Opus 5.5 / max, default fallback | 58.6% | 66.2% | 46.42 | Keep for architect: strong recall/judgment, but not the low-hallucination research preference. |
| Fable 5.1 / max, default fallback | 72.6% | 67.2% | 43.45 | Heavyweight architect option, not a calibration-led researcher choice. |

**Interpretation:** AA defines hallucination rate as `incorrect / (incorrect + partial answers + not attempted)`, not incorrect answers out of all questions. Accuracy is correct answers out of all questions. The index rewards correct answers, penalizes incorrect ones, and does not penalize abstention. Low hallucination alone can reward a model that seldom answers; therefore consider factual coverage, reasoning/tool competence, and direct research evidence too. These values do **not** establish citation fabrication, source entailment, or the same calibration under retrieved evidence. Max/fallback measurements are not silently transferred to the bundled high-effort setting. No synthetic composite rating or local research-harness result is claimed.

The audited core is intentionally **three suggestions**, not every model with a plausible research use; the released list also includes the user-selected GPT-5.6 Sol alternative. Researcher must admit evidence gaps, avoid unsupported completion, and validate consequential claim–passage entailment. Architecture is a separate quality-first workload: the user explicitly prefers heavyweight Opus/Astra/Fable, accepting their cost and calibration tradeoffs rather than filling that list with balanced models.

## Local validation still required

Run representative jobs with the same prompt, tool policy, endpoint, effort and budget. Record **cost per accepted result**, tool failures/retries, wall time including retrieval, p50/p95 first useful answer and completion, cache hit rates, and credential/tool limitations. Per role:

- Architect: requirements/constraint coverage, actionable plans, uncovered failure modes.
- Coder: accepted tested patch, regression rate, task completion cost and cycles.
- Reviewer: confirmed defects, false positives, severity calibration, smallest-local-fix compliance.
- Tasker: exact acceptance-check pass rate, short-job latency and cost; inability to solve an enormous feature is not a failure of the role.
- Writer: blind audience/voice preference and factual preservation at **medium**, not transferred max-effort Arena scores.
- Researcher: claim–source entailment, fabricated citation rate, version/commit accuracy, coverage of contradictory sources, independent-source handling, code path/line fidelity, retrieval budget and total time.

None of those local results is claimed here. Revisit temporary pricing at year-end, retest at the bundled efforts, and refresh recommendations when new task measurements or actual serving performance change.
